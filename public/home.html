How a fetch runs

Estimate, fetch, pause, read · 4 steps

  1. POST/fetch-jobs/estimate0 units

    Estimate the cost

    See the quota range for a channel before spending anything.

  2. POST/fetch-jobsqueued

    Start the job

    Send a URL, @handle or ID. The job ID comes back at once.

  3. GET/fetch-jobs/{job_id}paused

    Pause and resume

    When units run out the job keeps its cursor and continues after the reset.

  4. GET/channels0 units

    Read from storage

    Channels, videos, comments, playlists and transcripts, kept until you delete them.

Calling the API

A single-owner local service: one client key, sent as a header.

Send X-API-Key

curl -H "X-API-Key: $CLIENT_API_KEY" \
  http://localhost:8010/channels

The key is CLIENT_API_KEY in the project's .env. In the docs, use Authorize and paste only the value. Without it, protected routes answer 401; more than 60 requests a minute answer 429.

//health/api-docs/design-system

Ground rules

  • Secrets stay on the server. The Google API key and proxy URL never appear in a response, log or job record.
  • Kept until you delete it. Nothing expires on its own; refresh a channel to update it.
  • Honest data. Shorts is a duration heuristic and labelled so; hidden counts stay empty.
  • Public data only. No private analytics, growth history or writes to YouTube.
